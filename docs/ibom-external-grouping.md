# iBOM external grouping

How the injected bridge rebuilds the BOM rows of a generated InteractiveHtmlBom page from
NextIntranet's own BOM lines, and fills extra columns with live warehouse data.

## Why

The iBOM page is generated by KiBot, which merges rows by `Value + Footprint + UST_ID`. `UST_ID`
is frequently wrong in the source data, so unrelated parts get merged and identical parts get
split. The authoritative grouping already exists in NextIntranet: one `TemplateComponent` (BOM
line) per row, each with its own `refs`. The bridge replaces the generated grouping with that one.

Upstream iBOM is not patched. The bridge only rewrites the data `ibom.js` reads
(`pcbdata.bom.*`, `pcbdata.bom.fields`, `config.fields`, `settings.columnOrder`) and calls
`populateBomTable()` again.

## Where the code lives

| File | Role |
|---|---|
| `nextintranet_production/ibom_bridge_js/ni_bridge.js` | the injected script — single source of truth |
| `nextintranet_production/ibom_bridge.py` | reads that file and injects it before `</body>` |
| `nextintranet_production/ibom_bridge_js/harness.html` | offline test page, no server, no build |
| `assets/kibot/ibom_user.js` | **symlink** to `ni_bridge.js` for KiBot-side generation |
| `nextintranet_production/management/commands/reinject_ibom_bridge.py` | updates already-stored HTML |

The script is baked into each HTML file at upload time, so after changing `ni_bridge.js` existing
boards keep the old copy until:

```bash
docker compose run --rm --entrypoint "" web python manage.py reinject_ibom_bridge --dry-run
docker compose run --rm --entrypoint "" web python manage.py reinject_ibom_bridge
```

## Activation

The iframe URL is built in `ProductionPage.tsx` and carries `station_id`, `token`, `api_host` and
`template_id`. Grouping needs only `template_id` (plus `token` for the REST call), so it also works
in a tab opened without a station. Add `ni_grouping=0` to the URL to switch it off.

The live WebSocket channel and grouping are independent — either can be unavailable without
breaking the other, and with both down the page stays fully usable in its generated grouping.

## Data sources

1. **REST on startup and every 60 s**
   `GET /api/v1/production/templates/<template_id>/ibom-state/?stock=1`
   with `Authorization: Bearer <token>`. Same origin (the page is served from `/s3/...` through
   nginx), so no CORS involved.
2. **WebSocket push** — `ibom.grouping`, emitted by `useIbomBridge.ts` whenever it syncs state.
3. **Debounced refetch** (1 s) after any `ibom.sync` / `ibom.checkbox`, since progress changing
   usually means stock changed too.

The access token lives 60 minutes. After that the REST call 401s: the bridge logs it (never with
the URL — that is the one place the token would leak), flips the status to `stale`, and keeps
running on WebSocket pushes.

## Contracts

`ibom-state/?stock=1` — one entry per BOM line:

```jsonc
{
  "template_id": "…", "qty_planned": 10, "generated": "2026-08-01T18:29:07+02:00",
  "components": [{
    "id": "…",                    // TemplateComponent id — the grouping key
    "refs": ["R1", "R2", "R3"],
    "value": "10k", "footprint": "R_0603",
    "sourced_total": 0, "placed_total": 0, "qty_per_board": 3,
    "dnp": false, "exclude_from_bom": false,
    "component_id": "…",          // linked warehouse component, or null
    "component_name": "RES 10k 0603",
    // the rest only with ?stock=1
    "in_stock": 500, "needed_total": 30, "shortage": false,
    "total_in_home": 120, "location": "A1/Box3"
  }]
}
```

`ibom.grouping` over the station channel — the same data already flattened per designator:

```jsonc
{
  "type": "ibom.grouping",
  "payload": {
    "templateId": "…",
    "generated": "…",
    "patch": false,               // true merges, false/absent replaces
    "items": [
      { "ref": "R1", "line_id": "…", "part": "RES 10k 0603",
        "stock": 500, "needed": 30, "shortage": false, "location": "A1/Box3" }
    ]
  }
}
```

Matching is by `ref` (designator), because `refid` is just an index into `pcbdata.footprints` and
changes every time the page is regenerated. `refid` is accepted as an alternative. Designators the
board doesn't have are counted and warned about once, never fatal.

## Behaviour

- **Snapshot** is taken once from `pcbdata.bom.both`, not from `pcbdata.footprints`, so parts the
  generator filtered out (DNP, excluded) don't reappear. Every regroup starts from that snapshot.
- **Fallback** for designators with no BOM line: one row each, with `—` in `Part`. An empty `Part`
  means the opposite — the BOM line exists but has no warehouse component linked yet.
- **Columns** `Part`, `Stock` (`"500 / 30"`, prefixed `⚠` on shortage) and `Location` are appended
  to `config.fields`, padded into every row of `pcbdata.bom.fields` (lengths must match or the
  other columns shift), and inserted into `settings.columnOrder` before `Quantity`. Because they
  are real fields, header-click sorting works on them.
- **Values are escaped on ingest** (`& < > "`). iBOM writes field values through `innerHTML`, so
  unescaped API data would be an XSS vector.
- **Startup repaints the table once** after the columns are added, so the live columns are
  visible right away even while the first fetch is still failing.
- **Checkbox state survives regrouping**: `settings.checkboxStoredRefs` is keyed by footprint
  index, not row index.
- **Redraw** is debounced 120 ms and restores the highlighted footprint (`lastClicked`) afterwards.
- **Row order** is deterministic: known BOM lines first, then the leftovers, each by first
  designator in natural order (R2 before R10).
- **Unsupported layouts**: if the generator kept extra fields inline in the BOM rows instead of in
  `pcbdata.bom.fields`, the module logs a warning and disables itself; the rest of the bridge runs.

## Debugging from the browser console

```js
NIBridgeDebug.grouping.state()          // enabled, rows, mappedRefs, stale, lastUpdate
NIBridgeDebug.grouping.loadFromApi()    // force a REST refresh
NIBridgeDebug.grouping.applyItems([{ ref: "R1", line_id: "x", part: "test" }])
NIBridgeDebug.grouping.patchItems([...]) // merge instead of replace
NIBridgeDebug.grouping.clear()          // back to the generated grouping
NIBridgeDebug.getState()                // WebSocket side
```

The status dot in the top-right corner carries both states in its tooltip:
`NI bridge: connected` plus `grouping: 42 rows · updated 14:03:12`.

## Testing without the warehouse

Open `nextintranet_production/ibom_bridge_js/harness.html?template_id=harness` directly in a
browser. It provides a mock `pcbdata` whose `UST_ID` values are deliberately wrong in both
directions, plus buttons for the scenarios worth checking: full apply, patch, unknown designators,
empty response, garbage response, XSS payload, layer switching, grouped/ungrouped. The initial REST
fetch fails there on purpose — that is the degradation case.
